# 一、执行摘要

## 1. 现有视觉体系最可能过时的部分

"高饱和渐变＋大面积玻璃模糊＋发光边框＋持续漂浮动画"不宜继续作为全局视觉语言。

2026年近期奖站仍大量奖励动画、沉浸式和WebGL项目，但这恰恰说明奖站存在明显的"展示型网站偏差"：CSS Design Awards近期项目中，Spectral Field、Noho、homunculus、Motiondeep、/zeroz和Russell Numo均包含WebGL、视频、声音或重型动画，这些效果不符合本项目的离线、低性能和教学注意力要求。

更值得借鉴的是这些获奖项目背后的低成本视觉语言：

1. 强排版层级；
2. 清楚的网格；
3. 少量有意图的动画；
4. 细边框和明确表面层级；
5. 大面积安静背景；
6. 一个页面一个主视觉焦点；
7. 编辑式标题与小标签组合。

## 2. 最值得立即实施的5项升级

| 升级 | 决策 |
| ---- | ---- |
| 从"大面积玻璃拟态"改为"实体卡片＋1px边框＋轻阴影" | 立即实施 |
| 建立统一微动效Token，限制持续时间和位移 | 立即实施 |
| 页面只保留一个主焦点，解析默认折叠 | 立即实施 |
| 给按钮、卡片、题目统一触屏按压态 | 立即实施 |
| 给隐藏页面暂停动画，并加入减弱动画模式 | 立即实施 |

## 3. 最应限制的5项

* 大面积`backdrop-filter`；
* 全屏高饱和渐变；
* 永久循环的漂浮、脉冲和粒子；
* 页面切换前必须等待动画结束；
* 只有鼠标hover才能看到的说明。

## 4. 核心视觉判断

**玻璃拟态没有完全消失，但已经不适合做全局底座。**

建议保留：

* 封面或特殊总结页的一小块半透明表面；
* 弹层、浮动工具条的轻微透明；
* 不超过一个视觉区域的模糊效果。

建议取消：

* 每张卡片都模糊；
* 多层玻璃叠加；
* 玻璃卡＋发光边＋高饱和渐变同时出现；
* 阅读、真题和错题页面使用玻璃材质。

# 二、A1：2026近期网页设计趋势

## 2.1 本轮样本与限制

本轮检查了：

* Awwwards当前SOTD页面上2026年7月19日至8月3日的20个近期项目；
* CSS Design Awards当前页面及8个2026年7—8月WOTD；
* Land-book当前实时画廊中的8个首页条目；
* Godly当前已经跳转为Recent.Design，但公开解析页面没有呈现足够的作品标题、日期和标签，因此不计入严格日期样本。

因此：

```text
可核实具体日期的样本：28个
实时画廊辅助样本：8个
总观察样本：36个
```

Land-book明确说明画廊每日更新，其当前筛选项包含Cards、Gradient、Light Colors、Dark Colors、Pastel Colors、Visible Borders、Big Type和Typography等类型，但这些筛选项只能说明当下设计语言的存在，不能直接当作频率统计。

## 2.2 可落地趋势一：排版重新成为主要质感来源

近期样本中反复出现`typographic`、`minimal`和`one page`标签。Website Style采用minimal＋typographic，/zeroz和Russell Numo突出typographic，Noho与Motiondeep采用minimal或one-page结构。

### 对课件的意义

不要再主要依赖：渐变、光效、玻璃、插画数量来制造"高级感"。

应优先依赖：标题字号差、字重差、稳定行距、小标签、大数字、左对齐基线、留白、有意图的强调色。

### 推荐字体栈

因为不能联网下载字体：

```css
font-family:
  "Microsoft YaHei",
  "PingFang SC",
  "Noto Sans CJK SC",
  "Segoe UI",
  Arial,
  sans-serif;
```

数字、时间和分数使用：

```css
font-variant-numeric: tabular-nums;
```

### 实施级别

**立即实施。**

## 2.3 可落地趋势二：结构化网格，而不是自由漂浮

Cula Technologies的获奖页明确标注`grid`和`scroll`；Land-book当前样式筛选中也把Cards、Visible Borders和Big Type列为独立视觉类型。

### 适用页面

课程封面、学习目标、六色卡、单元总结、思维导图入口、数据摘要、错词列表。

### 不适用页面

长篇阅读正文、连续题目、需要从上到下阅读的语法解析。

### 推荐结构

```text
1张主卡
＋
2张次卡
＋
2—4张小信息卡
```

不建议一个页面出现8—12张等权重小卡片。

### 实施级别

**立即实施。**

## 2.4 可落地趋势三：明显边界回归

当前设计画廊继续提供Visible Borders、Cards和Flat Design等筛选，说明清楚的边界并没有被"无边界玻璃"取代。

### 项目落地

建议卡片采用：

```css
background: rgba(255, 255, 255, 0.94);
border: 1px solid rgba(32, 48, 64, 0.12);
box-shadow:
  0 1px 2px rgba(20, 32, 48, 0.04),
  0 8px 24px rgba(20, 32, 48, 0.07);
```

效果应像"经过设计的实体纸卡"，而不是漂浮的透明塑料。

### 实施级别

**立即实施。**

## 2.5 可落地趋势四：渐变仍存在，但更局部、更低对比

Land-book仍把Gradient列为当前风格类型，但近期奖站项目更多依赖排版、动画、网格和内容结构，而不是把强渐变作为唯一视觉主题。此处属于基于样本标签的趋势推断，不是严格频率研究。

### 建议

渐变用于：封面背景、卡片顶部2—4px色带、进度条、小范围状态高亮、六色卡的低饱和背景。

不用于：正文背景、每张题卡、阅读文章、大面积按钮、错误反馈。

### 实施级别

**立即实施。**

## 2.6 可落地趋势五：动效用于说明状态变化

Apple当前交互指南强调，动效应有目的、简短、精确，不应为了动而动，也不应迫使用户等待动画结束；频繁操作不宜反复播放显眼动画。

### 课件应优先动画化

卡片被选中、答案状态变化、错词进入复习池、解析展开、进度更新、页面共享元素变化。

### 不应动画化

每行文字、长篇阅读背景、导航永久呼吸、所有卡片永久漂浮、页面所有元素依次入场。

### 实施级别

**立即实施。**

## 2.7 可落地趋势六：浅色内容区＋少量暗色强调

Land-book当前同时保留Light Colors、Dark Colors、Black & White和Pastel Colors等筛选，说明2026不存在唯一流行配色。

对教育课件而言，更合理的是功能分工：

| 场景 | 推荐 |
| ---- | ---- |
| 阅读、语法、真题 | 浅色背景 |
| 封面、章节过渡 | 可用暗色 |
| 游戏 | 可提高饱和度 |
| 总结 | 中性浅色＋强调色 |
| 错误解析 | 浅色，不做暗黑警报式处理 |

### 实施级别

**立即实施。**

## 2.8 可落地趋势七：大标题＋小标签＋数字信息

近期获奖和画廊项目持续强调typographic和Big Type，但课件不应复制商业站的超大字体占屏效果。

建议：

```text
小标签：环节、题型、优先级
主标题：当前任务
辅助行：一句操作说明
数字：题号、时间、进度
```

例如：

```text
CORE · GRAMMAR

Did 后为什么必须用动词原形？

03 / 08
```

### 实施级别

**立即实施。**

# 三、A2：微动效高级感与廉价感

## 3.1 证据边界

官方指南支持以下原则：动效应简短、有目的；不得遮盖内容；高频操作不要播放显眼动画；用户不应被迫等待；重要信息不能只靠动画表达；应响应减弱动画偏好。

官方指南没有给出适用于本课件的唯一毫秒值。因此下表中的具体数值属于**项目初始参数**，需要在触屏教室中验证。

## 3.2 推荐参数

| 场景 | 项目初始时长 | 位移或缩放 | 缓动 | 决策 |
| ---- | ---: | ---: | -- | -- |
| 按钮按压 | 100—150ms | `scale(.98)` | ease-out | 立即 |
| 按钮恢复 | 140—180ms | `.98→1` | ease-out | 立即 |
| 卡片进入 | 180—240ms | Y轴6—10px | ease-out | 立即 |
| 页面切换 | 220—300ms | X轴8—14px | ease-in-out | 立即 |
| 正确反馈 | 180—240ms | `scale(1.015)` | ease-out | 立即 |
| 错误反馈 | 180—220ms | 左右4px，最多2次 | ease-out | 立即 |
| 翻牌 | 320—420ms | Y轴旋转180° | ease-in-out | 中期 |
| 解析展开 | 180—260ms | 透明度＋少量位移 | ease-out | 立即 |
| 拖拽吸附 | 140—200ms | 4—8px | ease-out | 中期 |

## 3.3 推荐Token

```css
:root {
  --x26-motion-instant: 100ms;
  --x26-motion-fast: 150ms;
  --x26-motion-base: 220ms;
  --x26-motion-slow: 320ms;

  --x26-ease-standard: cubic-bezier(.2, 0, 0, 1);
  --x26-ease-enter: cubic-bezier(0, 0, .2, 1);
  --x26-ease-exit: cubic-bezier(.4, 0, 1, 1);

  --x26-tap-scale: .98;
  --x26-card-shift: 8px;
  --x26-page-shift: 12px;
}
```

## 3.4 高级感规则

显得精致：小幅位移、单一方向、快速结束、动画与操作结果一一对应、动画中仍可点击、第一次明显后续减弱、进入退出方向符合空间逻辑。

显得廉价：大幅弹跳、超过两次回弹、所有卡片漂浮、每次点击都播放烟花、阴影和发光持续呼吸、文本逐字飞入、页面元素从多个方向同时进入、动画播放期间禁止操作。

## 3.5 触屏区别

触屏没有可靠hover状态，因此：

```text
hover = 只能作为鼠标增强
active/tap = 必须存在
focus-visible = 键盘必须存在
```

Apple指南指出直接触摸可以使用比触控板更明显的反馈，但不同输入方式仍应保持一致、可预测。

# 四、A3：教育场景的克制美学

## 4.1 研究支持的原则

多媒体学习研究支持：删除与教学目标无关的材料；用颜色、箭头和层级提示重点；把相关文字和图形放在空间上靠近的位置；避免布局迫使学生来回搜索；把复杂内容分段呈现。

2026年的在线学习线索干预Meta分析纳入40项实验或准实验研究、共5,049名参与者，进一步研究了线索对注意引导、认知负荷和学习结果的影响；但在应用到中国初中英语前，仍需查看年龄、学科和材料类型的调节结果。

系统综述也提醒，既有认知负荷研究较多集中在高等教育和STEM领域，因此不能把具体页面字数或卡片数量包装成初中英语的确定科学阈值。

## 4.2 MUST

* 每页标题必须说明当前任务；
* 一个页面只设一个主操作；
* 重点内容与对应题目空间靠近；
* 解析默认折叠；
* 正确答案、依据和迁移题按顺序展开；
* 阅读页面的背景和动效必须比游戏页面安静；
* 视觉强调色每页原则上不超过两类；
* 正误不能只靠颜色。

## 4.3 SHOULD

* 一题一屏用于诊断、真题和Exit Ticket；
* 同类型的2—4道短题可以同页；
* 页面保留明确的题号和总数；
* 预计时间只在任务开始处展示，不持续倒计时；
* 次要信息使用小标签，不与主标题争夺注意力；
* 图片、动画和文字不要同时自动运动。

## 4.4 MAY

* 章节过渡页使用较强视觉；
* 游戏模块使用适量插画；
* 总结页使用成长动画；
* 封面使用局部玻璃或微纹理。

## 4.5 MUST NOT

* 长阅读正文后面运行背景动画；
* 用闪烁或呼吸光提示重点；
* 同时突出三处以上内容；
* 自动播放声音；
* 把重要操作隐藏在hover；
* 为了漂亮拆散必须同时比较的内容；
* 把每页都设计成不同视觉风格。

# 六、A5：性能预算与verify_v2软检查

## 6.1 官方性能依据

典型60Hz屏幕每帧约16.66ms，但浏览器自身也需要时间，web.dev建议动画相关工作尽量控制在约10ms以内。

动画优先只改变`transform`和`opacity`，避免动画化`width`、`height`、`left`和`top`等会触发布局或绘制的属性。

布局读写交错会导致强制同步布局和layout thrashing；应先批量读取尺寸，再批量写入样式。

`will-change`不能作为全局"性能开关"，MDN建议仅在已有性能问题时少量、短时使用；应用到大量元素或父级容器可能增加资源消耗，反而变慢。

`content-visibility`可减少离屏内容的布局和绘制工作，并在2025年成为三个主要浏览器引擎均支持的Baseline特性；但项目仍需测试现有page-id显示逻辑和可访问性。

## 6.2 推荐运行预算

| 指标 | 目标 | 性质 |
| ---- | --: | ---- |
| 动画帧工作 | 尽量≤10ms | 官方建议映射 |
| 长任务 | 单任务不超过50ms | 官方定义 |
| 核心点击响应 | ≤200ms | 官方良好INP阈值 |
| 同时循环动画 | ≤2个 | 项目经验 |
| 活动Canvas | 同时≤1个 | 项目经验 |
| 大面积模糊层 | 当前页≤1个 | 项目经验 |
| 页面离开后循环任务 | 0个 | 项目硬建议 |

超过50ms的主线程任务会被视为Long Task，并可能阻塞点击和触屏响应；web.dev把200ms或更低作为良好INP阈值。

## 6.4 浏览器运行时软检查

```javascript
(() => {
  const warnings = [];

  /* Long Task：只用于支持该API的浏览器 */
  if ("PerformanceObserver" in window) {
    try {
      const observer = new PerformanceObserver((list) => {
        for (const entry of list.getEntries()) {
          if (entry.duration > 50) {
            warnings.push({
              type: "long-task",
              duration: Math.round(entry.duration)
            });
          }
        }
      });

      observer.observe({ entryTypes: ["longtask"] });
    } catch (error) {
      console.info("Long Task监测不可用", error);
    }
  }

  /* 检查隐藏页面中的运行中动画 */
  function inspectHiddenAnimations() {
    const pages = [...document.querySelectorAll(".page")];

    for (const page of pages) {
      const hidden =
        page.hidden ||
        getComputedStyle(page).display === "none";

      if (!hidden) continue;

      const running = page
        .getAnimations({ subtree: true })
        .filter((animation) => animation.playState === "running");

      if (running.length) {
        warnings.push({
          type: "hidden-animation",
          page: page.id,
          count: running.length
        });

        running.forEach((animation) => animation.pause());
      }
    }
  }

  window.x26PerformanceWarnings = warnings;
  window.x26InspectHiddenAnimations = inspectHiddenAnimations;
})();
```

Long Tasks API可以报告超过50ms的任务，但目前较新的Long Animation Frames API正在逐步取代它，因此只应作为兼容性允许时的诊断工具，不应成为课件核心功能。

## 6.5 content-visibility中期实验

可以在测试分支尝试：

```css
.page:not(.active) {
  content-visibility: hidden;
}
```

或对长滚动内容：

```css
.long-section {
  content-visibility: auto;
  contain-intrinsic-size: auto 700px;
}
```

风险：可能影响现有页面测量、打印、截图、查找和无障碍树；与现有隐藏机制重复。

**实施级别：中期验证，不直接进入全局模板。**

# 八、现在就改

1. 封面保留局部渐变，去掉大面积玻璃卡；
2. 普通卡片统一实体白色表面、细边框、轻阴影；
3. 加入`x26-`视觉Token；
4. 按钮增加触屏按压态；
5. 每页只保留一个主视觉焦点；
6. 解析区默认折叠；
7. 全局加入`prefers-reduced-motion`；
8. 页面离开后暂停动画、Canvas和计时器；
9. verify增加无限动画、模糊和`will-change`软检查；
10. 阅读、真题和错题页面取消装饰性持续动画。

# 九、收集数据后再改

1. `content-visibility`：测试10个课件、至少两类Windows设备；
2. 翻牌时长：比较320ms与400ms；
3. 页面切换：比较220ms与280ms；
4. 渐变强度：比较8%与14%透明度；
5. 卡片圆角：比较14px与18px；
6. 页面进入动画是否只在首次播放；
7. 触屏错误摇动是否引起不适；
8. 暗色章节页是否影响后续阅读适应；
9. 进度环是否优于普通进度条；
10. 当前页同时运行1个或2个动画的性能差异。

# 十、明确不改

* 不引入WebGL；
* 不引入Three.js；
* 不引入在线字体；
* 不引入Lottie CDN；
* 不使用全屏粒子背景；
* 不做自动滚动叙事；
* 不使用隐藏导航；
* 不让动画阻塞答题；
* 不把所有页面改为暗色；
* 不把商业奖站的沉浸感等同于教学质量。
