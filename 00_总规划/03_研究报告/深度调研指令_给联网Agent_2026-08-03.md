## 二、项目背景

### 2.1 目标课件形态

目标课件具有以下固定条件：

* 单个离线HTML文件；
* 无CDN；
* 无npm；
* 无构建工具；
* 无后端；
* 无联网依赖；
* 无账号登录；
* 触屏教室优先；
* 同时支持鼠标和键盘；
* 学生年龄12—15岁；
* 中国初中英语、中考英语背景；
* 一对一辅导为主，也可能用于学生自助学习；
* 每课约40—45页；
* 单文件体积不低于150KB，但禁止无意义凑体积；
* 需要保存答题记录并导出JSON或CSV；
* 课件需要在普通Windows电脑、触控屏和平板上稳定运行。

### 2.2 技术红线

研究过程中自动过滤以下方案：

* 依赖npm安装；
* 依赖React、Vue、Next.js等构建流程；
* 依赖服务器或数据库实时连接；
* 依赖CDN；
* 依赖云端API才能完成核心功能；
* 依赖WebGL或Three.js；
* 依赖付费库；
* 依赖商业授权素材；
* 需要用户登录；
* 需要持续联网；
* 需要高性能显卡；
* 仅适合鼠标hover、无法触屏；
* 无法降级为普通HTML/CSS/JavaScript的方案。

可以研究这些方案的视觉或交互思想，但必须将其转换为：

```text
纯HTML
+
纯CSS
+
原生JavaScript
+
内嵌SVG
+
可选Canvas 2D
```

不得直接建议引入原项目无法使用的技术栈。

### 2.3 现有项目修改边界

视觉和交互升级只能通过以下路径实施：

```text
CSS_EXTRA覆盖
+
js_extra增强
+
生成器模板更新
```

以下底座禁止直接修改：

```text
CORE_CSS
CORE_JS
courseware_core.py
```

因此，所有前端建议必须说明能否注入现有结构。

重点适配对象：

* 封面；
* 页头；
* 导航；
* 普通内容卡；
* 词汇卡；
* 六色卡；
* 翻牌卡；
* 选择题；
* 填空题；
* 阅读双栏；
* 解析面板；
* 总结页；
* 思维导图页；
* 按钮；
* 进度条；
* 正确与错误反馈；
* 弹层；
* 复习游戏。

不得把"重构整个DOM""重写导航系统""改用框架"作为主要建议。

### 2.4 现有教学结构

现有项目包含固定教学环节，主要涉及：

```text
复习导入
新词学习
语法精讲
随堂演练
阅读理解
自然拼读或发音
课堂游戏
课堂总结
思维导图
```

项目材料中如果出现"8段式"和"9环节"两种口径：

* 不得自行统一；
* 应列为规范口径冲突；
* 以实际项目主规范和生成器为准；
* 研究报告只评价教学顺序和各环节功能，不擅自修改页数及环节契约。
