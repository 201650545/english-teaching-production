# GPT 对话流程规范（2026-08-06 · 教师拍板）

> **用途**：规范「向 ChatGPT 提问/发包」的前置流程，确保 GPT 每次都能基于**最新、完整**的项目上下文回答。
> **适用范围**：所有发给 GPT 的研究问题包、方案请求、审计包。

---

## 一、每次问 GPT 前三步（必做）

1. **让 GPT 先看 GitHub 仓库，了解我们的结构**
   - 主仓库：`201650545/english-teaching-production`（教学生产体系：规范/工具/命令/样例）
   - 数据仓库：`201650545/feishu-data-hub`（学生学习数据）
   - 在问题包开头写明：「请先阅读 GitHub 仓库 `201650545/english-teaching-production`，重点看 `00_格式规范/05_索引说明.md`、`00_格式规范/更新记录.md`、`00_总规划/README_索引.md`，建立项目全貌后再回答」。

2. **每次有更改，就要更新 GitHub 仓库**
   - 任何规范/工具/命令/交付记录变更落盘后，**同步到 `english-teaching-production` 并 push**，再问 GPT。
   - 同步范围：`00_格式规范/`（规范+更新记录+索引）、`00_工具/`（正式工具+词库 JSON，**不含** `_`/`fix_` 临时调试脚本）、`00_总规划/`（当前命令 + 02/03/04/05 子目录，**不含** `06_归档/` 与 zip）、`样例课件/`、`README.md`。
   - 同步方式：手动（当前决策，不配 Actions 自动同步）。本地 staging 仓库在 `C:\Users\郭永涛\AppData\Local\Temp\eng-teaching-up`，`git add -A && commit && push origin main`。
   - **检查清单**：push 前跑 `git status` 看是否干净；新增的临时文件（`_*.py`/`fix_*`/`check_*`/zip）不入库。

3. **一定要补充上下文**
   - 问题包必须带：本次要解决什么、涉及哪些文件路径、已知限制/红线、希望 GPT 输出什么格式、以及「最近一次仓库更新到哪天」。
   - 上下文不足时先补再问，不允许空泛提问。

## 二、问题包格式（沿用 02_GPT问题包 编号）

- 命名：`GPT问题包N_主题_YYYYMMDD.md`
- 结构：背景 → 上下文与文件路径 → 问题清单（Q1/Q2/...）→ 期望输出格式 → 红线/约束
- 写好后把**文件路径**告知教师，由教师转发给 GPT。

---

## 三、GPT 交付后的处置（延续人机互查流水线）

- GPT 研究/方案交付 = **只审不执行**（Claude 审阅、整理落规范）；执行 Agent 负责本地实现。
- 交付落到规范/命令后，**同步 GitHub 仓库**（回到步骤 2）。
