# 交互形式菜单与选择题转化研究答复

> 版本：2026-08-05（重新生成）  
> 适用：离线单文件HTML、触屏优先、无第三方依赖  
> 边界：只出方案、菜单、轮换、校验与实现建议，不产出学生成品。

## 一、执行摘要

L07/L09的主要问题不是“按钮数量大”本身，而是同一种认知操作和手部动作连续重复。治理路径：

1. 建立交互形式菜单；
2. 题目先按知识目标筛选模板，再用稳定种子轮换；
3. 统一输出互动元数据；
4. 在`verify_v2`检查选择题占比、动作多样性、纯识别比例和每页题量；
5. 先修L07/L09热区，再把机制入库。

六种主动作：

```text
point 点 / drag 拖 / write 写 / link 连 / order 排 / listen 听
```

动作多样性不等于认知多样性。每个模板同时标记：

```text
action_type
cognitive_level = recognition / retrieval / application
```

## 三、Q2：转换映射与配比

### 无损转换条件

删除选项后仍需满足：

1. 唯一答案；
2. 答案形式是本课目标；
3. 不依赖多个近义选项比较；
4. 不破坏正式真题题型；
5. 学生有足够前置知识或支架。

### 原题转换

1. `This is not my pen. ___ is blue.`  
   改成无提示输入`Mine`；或先归类`mine/my/me`再填空。

2. `I like ___. It's very sweet and red.`  
   直接删除选项不完全无损。应增加草莓图片后输入`strawberry`，或用`straw + berry`排序再遮盖输入。

3. `— ____ is the museum? — It's on Center Street.`  
   可改成输入`Where`；或先做疑问词—答语连线。

4. `— ____ you go to the museum yesterday? — By bus.`  
   可改成句块排序`How / did / you / go...`，或双空输入`How did`。

### 中等层V1.0硬线

```text
全课选择题占全部可计分互动题 ≤ 45%
语法/词汇/综合诊断热区选择题 ≤ 35%
纯识别题 ≤ 50%
```

分母按题目容器计数，不按A/B/C/D按钮数计数。

三档启动阈值：

| 层级 | 全课选择上限 | 热区上限 | 纯识别上限 |
|---|---:|---:|---:|
| 基础 | 55% | 45% | 60% |
| 中等 | 45% | 35% | 50% |
| 培优 | 30% | 25% | 35% |

### 阅读单选边界

阅读正式单选保留，但每篇至少满足：

```text
每3道单选配1个证据定位任务
或
每篇至少1道短答/摘要/依据题
```

正式模拟课可声明`lesson_mode=exam_simulation`例外。

### 每页题量

```text
语法/词汇：选择≤2道；输入/改错/排序≤2道；大型拖拽/连线≤1组
综合诊断：最多2道正式选择 + 1道短操作/生成
阅读：短选择2—4道；长选项或详细证据1—2道
```

## 四、Q3：按课轮换机制

不使用单一`lesson % N`。流程：

```text
内容类型筛选
→ 学生层级筛选
→ SHA-256稳定排序
→ 最近两课避重复
→ 当前课动作平衡
```

推荐种子：

```text
interaction-v1|level|lesson_id|knowledge_id|section|slot_id
```

现有封面/词汇卡`lesson % 3`继续独立运行。视觉回答“长什么样”，互动回答“学生做什么”。

规则：

- 同知识点当前课不重复同模板；
- 最近2课尽量不重复；
- 连续两页相同主动作原则上禁止；
- 候选不足时可放宽并记录`rotation_relaxed=true`；
- 不为轮换选择不适合内容的模板；
- 相同课程卡、菜单版本和历史记录必须生成相同结果。

动作要求：

```text
基础≥3种 / 中等≥4种 / 培优≥5种
```

## 五、Q4：verify校验

新题容器建议输出：

```html
<div
 data-interaction-item="1"
 data-question-id="L10_G22_01"
 data-knowledge-id="G22"
 data-section="grammar"
 data-template-id="G-WRITE-FORM"
 data-interaction-type="fill_text"
 data-action-type="write"
 data-cognitive-level="retrieval"
 data-scorable="true">
</div>
```

新课件加入：

```html
<!-- CW-INTERACTION-CONTRACT:1 -->
```

检查编号：

- `VIS-601`：全课选择题占比；
- `VIS-602`：热区选择题占比；
- `VIS-603`：全课动作种类；
- `VIS-604`：主要环节动作种类；
- `VIS-605`：每页题量；
- `VIS-606`：纯识别比例；
- `VIS-607`：连续选择主导页；
- `VIS-608`：知识点是否有提取/应用证据；
- `VIS-609`：同知识点模板重复；
- `VIS-610`：互动元数据完整性；
- `VIS-611`：旧HTML选项按钮事故信号；
- `VIS-612`：阅读单选证据闭环。

旧HTML事故信号仅WARN：

```text
全课quiz-opt按钮>160
单页>12
连续3页均>8
```

`--force`必须同时提供审计日志，不能隐藏违规。

## 六、Q5：实施顺序

### 阶段0：补元数据合同

只改生成器和组件输出，不改CORE。

### 阶段1：修L07/L09热区

L07优先p28—p40：

```text
每4题组 = 1选择 + 1输入/拼写 + 1拖/连 + 1迁移
```

L09优先p22/p24/p26/p29/p34/p35/p37：

```text
≤2道选择 + 1组排序/连线 + 1—2道输入/情境应用
```

验收：

```text
全课选择≤45%
热区≤35%
全课≥4种动作
连续选择主导页≤2
阅读保留单选并连接证据
```

### 阶段2：菜单入库

新增：

```text
interaction_menu_v1.json
interaction_rotation_v1.py
interaction_history.json
```

### 阶段3：组件适配

优先复用拖拽、填空、GM-V02、GM-G03、GM-R06、排序、听写翻牌和点词选义。

### 阶段4：verify入库

`VIS-601—612`先WARN运行2—3课；计数确认后，对新合同课件将601、602、603、610升级ERROR。

### 阶段5：规范同步

同步01、07、08规范及更新记录。代码未回归前不得写成“已经实施”。

## 七、明确不做

- 不把所有选择题机械改成拖拽；
- 不以六种动作都出现替代知识目标；
- 不改变正式阅读原题题干和选项；
- 不新增第三方拖拽库；
- 不记录触屏坐标和拖拽轨迹；
- 不把视觉换皮算作新题型；
- 不改`CORE_CSS`、`CORE_JS`或`courseware_core.py`；
- 不新增第二套学习数据库；
- 不把45%、35%称为科研定律。

## 八、证据边界

研究支持检索、生成和反馈，但不直接证明六种手部动作的固定配比。45%、35%、动作数量和连续页限制属于基于本项目事故数据制定的V1.0工程阈值，需经L07、L09和至少2节新课回归后再升级正式规范。
