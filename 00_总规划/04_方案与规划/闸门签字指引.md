# 闸门签字指引（层① / 层②）

> **用途**：让教师明确"在哪两个文件、签什么、签完有什么效果"。三个闸门中，层①与层②由教师在对应文件签字完成；exam_spec 锁定见 `exam_spec锁定核对清单.md`。
> 日期：2026-08-02

---

## 闸门全景

| 闸门 | 文件 | 现状 | 签字动作 | 签后效果 |
|---|---|---|---|---|
| 层① 总规划 | `00_总规划\总规划.md` | ⏳ 待签 | §6 审批区签字 | 允许对表内学生出具《学生规划》（层②） |

> **顺序**：先层① → 再层② → 后 exam_spec（逻辑依赖，但可同日完成）。

## 层① 签字（`00_总规划\总规划.md`）

打开文件末尾 **§6 审批区**（约第 73-80 行）：

```
## §6 审批区（层①）

☐ 通过，允许对表内学生出具《学生规划》    ☐ 需修改（意见如下）

修改意见：

签字：________　日期：________
```

**动作**：
1. 将 `☐ 通过` 改为 `☑ 通过`（或在"通过"前打勾）
2. 在 `签字：________` 填上姓名，`日期：________` 填日期
3. 若需修改，勾选"需修改"并填意见，引擎据此修订后重签

## 层② 签字（`许颖嘉\许颖嘉_学生规划.md`）

打开文件末尾 **§7 审批区**（约第 76-86 行）：

```
## §7 审批区（层②）

前置条件：层①《总规划》☐ 已通过（日期：____）

☐ 通过，开始生成（首课＝L5）    ☐ 需修改：

| 字段 | 原值 | 改为 |
|---|---|---|
| | | |

签字：________　日期：________
```

**动作**：
1. 前置条件栏：若层①已签，填 `☑ 已通过（日期：____）` 及日期
2. 将 `☐ 通过` 改为 `☑ 通过`，确认首课＝L5
3. 签字 + 日期
4. 若需修改，用下方表格"字段/原值/改为"写明，引擎据此修订

> 另外 §2 有「AI 定级建议 · 教师确认：☐ 同意　☐ 覆盖为」——若同意基础级，可顺手勾"同意"。

---

## 签字完成后

1. 通知执行 Agent（本会话）
2. Agent 执行：
   - 核实两份文件签字栏已填
   - 若 exam_spec 核对清单也已签 → 置 `locked=true` + 更新记录.md 登记
   - 三闸门全开后 → **正式投产 L5 四件套**（`许颖嘉\第05课时\`）
3. 首课产出前，按流程仍会**询问是否含听力**

---

## 常见疑问

- **Q：签字后旧文件会被动吗？** 不会。重出旧课件（L2/L4 等）仍需单独批准，与本次闸门无关。
- **Q：能先只签层②吗？** 不能，层②前置条件是层①通过。
- **Q：签字用电子还是手写？** 在 md 文件里填入姓名文本即可，无格式要求。
