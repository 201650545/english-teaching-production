- **事故**：为修复一处 CSS 重复（`.rule-card` 定义两次），执行 AI 把整个视觉层 `eng.CSS_EXTRA` 删掉，导致页面 60+ 处视觉类全部失去样式，渲染成裸文本；而结构校验（verify_v2）照样 PASS——它不查视觉。

## 问题一：HTML 课件 CSS 架构治理（防"修一处毁一片"）

**事故**：`.rule-card` 在 base CSS、组件 CSS、主题 CSS 三处重复定义，执行 AI 为去重而**删除了整个视觉层**，页面 60+ 类无样式，渲染崩坏；而自动校验仍 PASS。

**请回答**：
1. 离线单文件 HTML 课件（无构建工具、无外部资源、需离线双击即用）的 **CSS 架构最佳实践**是什么？如何组织 base / 组件 / 主题覆盖三层，既允许主题改色又不互相覆盖崩溃？
2. 如何用**命名、层叠约定或简单机制**防止"为修一处删掉整层"这类误删？CSS 自定义属性（CSS variables）+ `!important` 的正确用法边界是什么？
3. 设计一套**CSS 完整性自动校验**：如何检测"页面用到的 class 没有对应样式定义"？给一个可放进 verify_v2 的检查清单（如：HTML 中出现的每个 `class="xxx"` 是否都在 `<style>` 中有选择器定义；检测到缺失即警告）。给出实现思路（纯 Python 正则/简单解析即可，不引第三方）。

## 问题二：一节课的教学容量（一课一种体裁 / 认知负荷）

**教师意见**：一节课塞两种作文体裁（书信+介绍），基础层学不过来。

**请回答**：
1. 一节课（90 分钟，12-15 岁）**合理的内容容量**是多少？一个核心知识点/技能点该学多深？（可参考认知负荷理论、工作记忆容量、一节课目标数量建议）
2. **体裁/题型一课一原则**是否成立？一个写作课该教几种体裁？如果一课只教一种（如只教书信），其余体裁如何安排（后续课轮换 / 只作变式）？
3. 给一个"一节课内容配比"建议：新授 / 示范 / 练习 / 反馈各占多少？培优与基础层差异？

## 问题三：把"好看"变成可自动校验的规则（视觉验收自动化）

**现状**：结构校验不查视觉，"PASS 但难看"；你上轮已给 verify_v2 软检查候选（字号<18px、例词长串、信息块过多、解析展开、装饰干扰等 14 项）。

**请回答**：
1. 基于你上轮的清单，给出**最终可执行的 verify_v2 视觉软检查规则 V1.0**（把每项的判定方式写清楚，如"例词长串=单节点 ≥6 个逗号分隔英文词"），并补充任何遗漏的高频"难看"信号。
2. 还有哪些"看一眼就发现丑"但**容易程序化**的检查？（如：连续多行同字号无层级、超宽阅读行、空页/过密页、色彩过度使用）
3. 验收流程建议：除了自动检查，人工逐页抽查该抽查哪几类页（封面/规则页/例题页/练习页）？给一个 5 分钟内可完成的抽查清单。

**输出要求**：每问 结论 + 依据（可附文献/链接）+ 可直接写进规范或 verify_v2 的规则清单；不泛泛而谈。
