# GPT 研究问题包 4 · 课件风格包与验证器边界（2026-08-06）

> **用途**：发给 ChatGPT 检索论证。项目采用「人机互查」流程——方案须经研究汇报支撑后再定稿。
> **请求**：请基于检索与教育课件设计研究，对下述 3 个问题给出**带依据的详细汇报**（引用来源），结论供我落规范。

---

## 一、项目背景（为什么问）

我们是初中英语教学资源流水线，为**三个学生**（许颖嘉=基础档 / 邓兴华=中等档 / 李民宪=培优档）批量生产 40-45 页网页课件（HTML，含答题/拖拽/连线/排序等交互 + IndexedDB 数据采集）。

**核心痛点**：课件视觉长期趋同——之前规范锁定"红金"默认模板 + 单一生成引擎输出统一 CSS_EXTRA，导致执行 Agent 产出的课件几乎一个模子（尤其 DeepSeek 生成的几乎雷同），教师明确反感（"太丑了，不喜欢一成不变"）。

**已做的调整（2026-08-06）**：
1. 写了《09_课件风格包规范.md》：定义 **10 套风格包**（S01-S10），每套含主色系/封面变体/组件建议/适用主题，让 Agent 按知识点自主选风格。
2. 验证器 `verify_v2.py` 视觉层放开：视觉 ERROR 从"阻止交付"改为"打印不阻止"；硬规则保留（体积≥150KB/页数40-45/答案分布≤40%/交互合同/数据采集/交互真实 VIS-613）。

**先例教训**：执行 Agent 曾为通过选择题占比硬线而**只换皮不真改**（贴元数据标签但 quiz-opt 原封不动），被 VIS-613 DOM 实测抓包。因此"放开视觉"存在被 Agent 钻空子的风险。

---

## 二、已定方案现状（供参考，非全对）

- 风格包划分维度：**按主题语义场**（博物馆/交通/侦探/自然/海洋/校园/杂志/游戏/手绘/极简 10 类）。
- 选包规则：主题语义场主判据；同学生相邻 3 课不重样；复习/检测课优先 S08(游戏)/S10(极简)。
- 验证器边界：工程硬规则必须 ERROR=0；视觉层（封面布局/主色/组件形态/CSS 杂项）放开，创新偏离书面说明即放行。

---

## 三、问题

### Q1 · 风格包变量体系：除了"主色+封面+组件"，还应包哪些变量？10 套划分会不会造成新的"10 套模板趋同"？

背景：我现在的风格包每套 = 主色系 + 封面变体 + 组件建议 + 适用主题。担心：如果只换色和封面、页面结构仍是同一套，长期看仍会趋同（变成"10 个皮肤"而非"10 种风格"）。

请论证：
- 教育课件"视觉风格"还应包含哪些**变量维度**（如版式系统/字体层级/动效语言/信息密度/图标语言/交互触感）？哪些最影响"观感差异"？
- 怎样让风格包是**参数化的风格变量**而非"又一叠死模板"？推荐一个最小但有效的风格变量集合。
- 10 套按主题语义场划分是否合理？会不会与"课型（授课/复习/检测）"和"学生档位（基础/中等/培优）"冲突？你推荐按什么维度组织风格体系？

### Q2 · 执行落地机制：文档是最弱一环，怎么让 Agent 真的按知识点选风格、真创新，而不是退回默认模板？

背景：三层防御诊断结论——"模板内建 > 校验器硬查 > 人工抽查，文档是最弱一环"。风格包规范只是文档，执行 Agent（含 DeepSeek 系）很可能无视它退回最熟练的模板。

请论证：
- 让执行 Agent 真正执行风格包的**可靠机制**有哪些？例如：① prompt 强制声明"本课用哪套风格包+主色值"并写入课程设计卡；② 把风格包做进生成引擎（现有 theme_colors.py 已做主题色注入，可扩展为 style_vars 注入封面/组件变体）；③ 校验器检查"风格声明 vs 实际 CSS"一致性；④ 人工抽查。
- 各机制的可靠性排序？最推荐哪种组合？
- 有没有方法让"创新"可量化验收（不只靠人工审美判断）？

### Q3 · 验证器放开后的质量护栏：视觉自由了，如何守住可读性/交互真实底线，又不死磕格式？

背景：verify_v2 视觉 ERROR 已改为不阻止交付。担心放开后 Agent 偷懒——换皮不真做交互、可读性崩坏（字太小/对比度不足/拥挤）、数据采集缺失。

请论证：
- 视觉放开后仍应保留哪些**软硬结合的视觉护栏**？例如：字号下限、文字背景对比度、可点区域最小尺寸、每页信息密度上限、动效可关闭。
- 这些护栏里哪些适合做成**校验器硬规则**，哪些只做软警告/人工项？
- 如何防"换皮"（视觉改了但交互是假的）？除了现有 VIS-613 DOM 实测，还推荐哪些低成本反作弊检查？
- 硬规则与视觉自由的边界你建议怎么划（给一个明确清单）？
